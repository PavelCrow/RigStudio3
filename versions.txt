---Version 3.25.2
Sleeve: fixed reaction on wrong side of the bend (bend vector sign)
Sleeve: fixed wild rotation on compound/large bends (bend math rewritten to use quaternions instead of per-axis Euler scaling)
Sleeve: fixed uneven ring joint spacing (ringAngle was silently stored in radians)
Sleeve: fixed wrong reaction when parent/driver are in unrelated hierarchies with mismatched axes (world mode)
Sleeve: renamed attributes - radius/spread/ringAngle/ringRadius/strength are now falloff/moveFactor/posAngle/initPos/moveMult
Sleeve: added manual offset control (circle, additive on top of the automatic reaction)
Sleeve: added falloff shaping with an on/off toggle (how many ring joints react, one to all)
Sleeve: added mirror (l_/r_) - builds both sides and connects all tunable attributes left to right

---Version 3.25.3
Sleeve: added direction controls (optional) - 4 triangles inside the main control splitting the ring into 4 smoothly blended regions
Sleeve: direction control move offsets the nearby ring joints on every axis, fading to zero at the neighbouring triangles
Sleeve: direction control rotateX/rotateY tilt their patch of the ring - joints under the triangle stay put, the ones either side move opposite ways on a sine curve (rotateZ stays a rotation)
Sleeve: direction controls carry their own moveOffset/slideOffset, additive on top of the group and per joint values
Sleeve: everything is built at unit size now - scale <name>_grp to resize the whole sleeve at once, carried over on rebuild
Sleeve: world mode measures the bend against an editable <name>_parentLoc locator, so parents with negative scale can be hand-corrected
Sleeve: renamed attributes - moveMult is moveFactor, slide is slideOffset, the triangles use moveOffset
Sleeve: triangle pivots sit at their own centre and their scale is locked
Sleeve: mirror no longer connects the triangles or the parent locator - they are per side hand-tuning

---Version 3.25.4
Fixed rig template loading after a new scene was created ("No object matches name: character") - the rig state in memory is now re-synced with the scene
rig.delete() no longer fails on a missing twists group, missing curveInfo nodes or a rig without a parent group, and always resets the rig state
rig.create() returns success, so template loading stops instead of renaming a root node that was never created
rig.create() checks the actual root node name instead of a hardcoded 'main'

---Version 3.25.5
fixed creating transform groups in joints chain in spine module.
batWing: fixed error on reconnecting the module to another poser (the mirrored l -> r connections were recreated on top of the existing ones)
batWing: the wing scales with the root joint of the parent module only - scaling the joint the wing is connected to no longer scales it
utils: implemented scaleFromRoot() - inserts a scale correction matrix into the connector matrix chain, keeping the target as an input so getParent() still finds it
docs: added docs/bifrost_to_plugin.md - working spec for replacing the Bifrost graphs of the modules with a plugin node

---Version 3.25.6
metahuman: new package for fitting a rig onto a referenced MetaHuman skeleton - a table of poser -> bone rules, saved as a reusable map, applied to the posers and then used to drive the skeleton
metahuman: placePosers() snaps every poser of the centre and the left side onto its bone; the right side is carried by the rig's own mirroring and is never forced
metahuman: a locked or driven channel no longer skips a poser - the free ones are still written, which puts it as close as the module allows (finger posers keep their plane, foot posers their line)
metahuman: placement order is the rigger's, not the hierarchy's - the ends of a chain go before its middle, since the elbow and the knee are judged against a hand and a foot already standing in place
metahuman: bindSkeleton() constrains the main body bones to the rig joints, finding each driver by measuring rather than by name; twists, correctives and the whole face are left to the plugin that drives them
metahuman: detach() takes the constraints back off, bindStatus() reports what is driving each bone right now
metahuman: the skeleton namespace is read from the scene on every run, so one map fits every character built on the same template
metahuman: the map carries a fingerprint of the rules it was built from, so a map left over from an older table says so instead of placing posers by it
main: MetaHuman buttons - set the skeleton root once, then place posers / connect / disconnect; they stay locked until the root is set

Целиться на соседнюю кость нельзя: сдвинь контрол вдоль кости, и она проедет мимо соседней, отрезок развернётся назад и кость уставится в середину цепочки. pk_twist: у драйвера выше цепочки поворот уже унаследован всеми костями, поэтому он гасится к дальнему концу, а не добавляется - плечо стоит, локоть идёт целиком. Определяется автоматически проходом вверх по иерархии
pk_twist: разница поворота драйвера считается в системе той кости, где висят твистовые кости: для драйвера сверху rotate * rest^-1, снизу rest^-1 * rotate. Обратный порядок разворачивает ось на саму позу покоя - на зеркальной стороне это меняло знак, и гашение превращалось в удвоение
