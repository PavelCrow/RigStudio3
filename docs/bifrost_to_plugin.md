# Перевод Bifrost-графов в плагин-ноду

Рабочая спека. Источник истины по этой задаче — этот файл; память Claude содержит
только указатель на него. Правится по ходу работы, снизу — журнал.

**Детальная спека ноды `pk_wing`** (интерфейс, разобранная математика графа,
план отладочной визуализации) — в [../plugins/pk_rigNodes/pk_wing_spec.md](../plugins/pk_rigNodes/pk_wing_spec.md).
Этот файл — про задачу в целом, тот — про конкретную ноду.

## Зачем

Тяжёлые Bifrost-графы тормозят загрузку сцены и требуют установленного Bifrost.
Цель — заменить их плагин-нодой: убрать JIT-компиляцию графа, снять зависимость
от Bifrost, получить читаемый и быстрый код.

## Инвентарь графов

Граф лежит в `modules/<name>/<name>.ma`, нод `bifrostGraphShape`, сам граф — в
атрибуте `.sc` как JSON.

| модуль | графов | размер |
|---|---|---|
| `wing2` | 1 | **2276 нодов**, 157 уникальных типов, вложенность 11, 37 портов |
| `mouth` | 3 | `zip` 74 нода / 15 портов, `sec_controls` 82 / 38, `bifrostGraphShape1` 359 — **тестовый, не нужен** |
| `eyelids` | 2 | не разбирал |
| `limbCurved` | 1 | не разбирал |

### Как читать граф из .ma

Собрать строковые куски `setAttr ".sc" -type "string" ( "..." + "..." );`,
склеить, снять эскейпы через `json.loads('"' + blob + '"')`, затем `json.loads`
результата. В JSON есть всё: `ports` (имя/тип/направление), `nodes` и
`compoundNodes` с `nodeType`, `connections` (`source` → `target`), `values`
(константы на портах), вложенные `compounds`.

### Кастомные компаунды

Исходники: `F:\Maya_Projects\_Bifrost_Compounds\pk_compounds\compounds` (23 json).
В `.ma` они только по ссылке, определений там нет.

- `wing2`: `pk_aim_matrix`, `pk_rotate_quaternion`, `pk_rotate_vector`
- `mouth`: `pk_lerp_matrix`, `pk_reverse`

## Что считает граф wing2

Чистая функция, без геометрии (`Geometry::` нодов нет), без симуляции и без
зависимости от времени.

**Входы (37):** float/bool/long + fcurve-порты — `length`, `bend`, `twist_root`,
`twist_tip`, `wide`, `root_pos`, `tip_pos`, `pos_2_offset`, `pos_3_offset`,
`length_min` (каждый как compound + `_A`), плюс `auto_twist_root/tip`,
`layers_count`, `layer_wide`, `layer_pos_min/max`, `layer_bend`,
`root_offset_1..7`, `mirror`, `flatten`, `debug_layer_id`.

**Выходы:** только массивы матриц — `out_controls_local_matrixes`,
`out_joints_in_matrixes`, `out_joints_out_matrixes` (+ вложенные `_A`/`_B`:
слои × перья × джойнты).

**Внутри:** самописный B-spline (`get_bSpline_knots`, `knot_vector`,
`get_zeroToSpans_knot_vector`, `first/last_multiplicity`, `find_span`, `deBoor`,
`sample_bSpline*`, `get_d1_bSpline_length1`, `measure_segments` — то есть
репараметризация по длине дуги), aim-матрицы с твистом, раскладка по слоям и
перьям. Циклы: 38 `for_each`, 33 `iterate`. Массивные операции:
`get_from_array` 275, `array_size` 89, `last_in_array` 80, `sequence_array` 40.

## Подход

**Переписывать по смыслу, НЕ транспилировать граф в код.** Причины:

- Неявная авто-итерация Bifrost: массив в скалярный порт авто-векторизуется.
  Для честного транспайла нужны сигнатуры (арность портов) всех типов нодов, а
  сигнатур `Core::*` в `.ma` нет — они в библиотеке самого Bifrost.
- Краевые случаи массивов (`get_from_array` за границей, пустые массивы,
  `array_bounds`, `find_all_true_in_array`) надо воспроизводить один в один.
- 2276 нодов сгенерированного кода никто не будет сопровождать.

Граф используется как спецификация. Задача узнаваемая (B-spline + репараметризация
по длине + aim-матрицы + раскладка по слоям), это несколько сотен строк внятного
кода.

**Цель — C++ `MPxNode`.** Python+numpy ложится хуже: циклы ветвистые,
векторизуется не всё. Стыкуется с планом по `rigTools/addSleeve.py` — один
плагин, несколько нод.

**Имена атрибутов сохранить как есть**: `modules/wing2/wing2.py` обращается к
`{name}_bifrostGraphShape.<attr>` напрямую (строки 116, 274, 318, 337) — тогда
python-часть почти не меняется.

## Порядок работ

1. **Замерить, что именно тормозит:** загрузка плагина Bifrost / JIT-компиляция
   графа при первой оценке / счёт на кадре. От этого зависит, окупается ли
   переписывание.
2. **Дешёвая альтернатива — проверить до плагина:** похоже, knot-векторы и спаны
   пересчитываются внутри циклов (22 `get_bSpline_knots`, 16 `find_span`/`deBoor`,
   89 `array_size`, 275 `get_from_array`). Вынос их из циклов может дать
   ускорение без всякого плагина.
3. **Пилот на `zip` из mouth** (74 нода, чистая математика + один `for_each`):
   обкатать скелет плагина, раскладку атрибутов, тест на совпадение.
4. **wing2** — основная работа. Сначала вычитать граф до однозначной спеки
   (11 уровней вложенности), потом код.
5. `eyelids`, `limbCurved` — по остаточному принципу.

## Проверка

Сцена, где Bifrost-граф и новая нода стоят рядом на одних входах. Прогон
случайных значений по всем 37 входам, сравнение выходных матриц с допуском
~1e-5. Граф из `.ma` не удалять, пока не совпадёт.
